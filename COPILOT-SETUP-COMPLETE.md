## 🎯 Core Principles (Now in Place)

### 1️⃣ Context-First Approach
- Check `COPILOT-INSTRUCTIONS.md` **FIRST**
- Use `context.json` for current project state
- Only scan repo if info is missing from context
- Never hallucinate or assume behavior

### 2️⃣ Three-Perspective Analysis
Every change analyzed from:
- **Project Side**: Code architecture, patterns, dependencies
- **Cloudflare Side**: Deployment, configuration, worker behavior  
- **Google Side**: SEO impact, indexing status, canonical URLs

### 3️⃣ Expertise-Based Fixes Only
- Every fix must be justified with reasoning
- Never apply random or theoretical changes
- Verify changes from existing code
- Ask for clarification if unclear

### 4️⃣ Single Context File with Dates
- Use `COPILOT-INSTRUCTIONS.md` as main file
- Add dated change log entries (not new files)
- Don't create multiple context files
- Update same file with dated sections

## 📊 How Copilot Should Work Now

### When Starting Any Task
```
1. Open COPILOT-INSTRUCTIONS.md
2. Check context.json for current state
3. Reference relevant section for your task
4. Follow the analysis checklist
5. Implement with justification
6. Document with date in change log
```

### When Proposing Changes
```
1. Identify the problem clearly
2. Analyze from 3 perspectives
3. Justify the fix with reasoning
4. Ask for confirmation before major changes
5. Test locally before suggesting deploy
6. Add dated entry to change log
```

### When Handling Requests
```
1. Check if info exists in context files
2. Ask for clarification if unclear
3. Provide three-perspective analysis
4. Explain deployment impact
5. Confirm SEO/Google Console implications
6. Get user approval before proceeding
```
